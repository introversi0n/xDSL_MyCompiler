# 开发与学习约定

[回到总方案](总方案.md)

## 1. 文件按需要增加

不先建空目录或空文件，不为了结构对称写重复实现。初期 `tools/my_opt.py` 自包含，使用普通函数和清楚的注释段：参数 → Context → 注册 → 解析 → 验证 → Pass → 打印。

工具脚本允许同一个文件包含简单注册表。出现自定义 Dialect/Pass 模块或多个工具真正需要复用时，再建立 `xdsl_mycompiler/` 包。C++ 仅作阶段文档中的接口、目录和构建对照，不建立 C++ 编译器或动手构建任务；已有 include/lib 不作为 Python 包。添加包配置前先说明必要性，不为了“以后可能需要”增加插件、工厂层、继承层或配置格式。

已有文件可能是用户工作，删除前先检查；只删除明确不需要的项目自有冗余实现。

## 2. 示例和习题配套

- **示例**：助手提供最小可运行代码及输入，逐段说明。
- **习题**：用户完成少量关键逻辑，例如注册一个 Dialect、补一个 Pass、读取 use.index。提示具体，不直接填完答案。
- **验收**：给一条命令和明确的期望，先用最小数据判断对错。

示例代码中的形式：

```python
# 1. 创建 Context
# MLIR 对应：MLIRContext。xDSL 将部分注册工作放在 Context 中。
ctx = Context()

# 2. 注册示例需要的 Dialect
ctx.load_dialect(builtin.Builtin)

#TODO[USER][stage01-U1] 在独立练习脚本中补 func/arith 注册，观察缺少注册时的错误。
```

不让练习破坏主示例。首阶段确有练习需求时才新增 `tools/exercises/stage01_context.py`；不复制完整 my-opt，只保留练习所需的少量代码。

## 3. 所有未完成事项统一索引

Python 使用注释；Markdown 使用 HTML 注释；将来 C++ 用包含相同标记的注释：

```text
#TODO[AGENT][stage01-A1] 助手待实现的工作
#TODO[USER][stage01-U1] 用户习题
#TODO[PLAN][stage09-P1] 尚待确定的方案
```

```markdown
<!-- #TODO[PLAN][stage09-P1] 确认动态 shape 的范围。 -->
```

在 VS Code 项目级搜索 `#TODO` 查全部事项，搜索 `[USER]` 查习题。未创建的代码所对应任务先写在阶段文档，不为了放 TODO 创建空代码。

公开版本保留 `#TODO[USER]` 作为练习题，不将其计入项目缺陷或待交付功能。学习者可在自己的副本中填写答案、删除对应标记并记录心得。`#TODO[AGENT]` 和 `#TODO[PLAN]` 则表示真实的实现/方案待办，完成后更新日志并移除。不能因为示例测试通过就声称已经检查了学习者的答案。

## 4. 文档和代码双向维护

- 总方案：阶段入口、范围和状态。
- 阶段方案：涉及文件、学习内容、任务/习题、运行方法与验收。
- 代码文件头：链接到相应 `docs/stage-XX-*.md`，关键段旁标明 MLIR 对应类/方法和差异。
- 阶段文件内的开发日志：改了哪些文件、学了什么、实际运行结果、未完成项；不单独建全局日志，不写预估开发日期。
- MLIR/C++ 目录、接口与构建说明也写在相应阶段文件；后续阶段未开始时只在总方案保留设计，不提前建阶段文档。

改变命令、文件路径、Pass 名称时，同步更新阶段文档与 README 中涉及的命令。改变整体范围或先后关系时，再同步总方案。

合并旧方案时保留决策，而不是只删除文件：说明旧职责是保留、合并到哪个位置，还是推迟到哪个阶段。尤其不能丢掉输入输出对拍、独立习题、C++ 构建理解和框架能力边界。

自定义 Dialect/Pass 所在阶段必须同时说明：Python 模块/导入/注册，以及 C++ `.td/.h/.cpp/.inc`、生成目标、编译库、链接与注册；标明不是所有 C++ Pass 都必须有 `.td`，也不是 Python 需要照搬头源分离。

## 跨平台运行

阶段文档直接列出 `python ...` 命令，不维护 .ps1/.sh/.bat 启动器。命令以项目根为工作目录，路径使用相对路径；Python 内使用 pathlib，读写文本注明 UTF-8。不得依赖固定盘符、Conda 环境名、shell 变量或平台专用命令。

依赖安装使用 `python -m pip`，退出码检查需要演示时使用 Python subprocess。可移植设计不等于三平台都已验收；开发日志如实记录实际测试环境。

正常示例应成功，故意错误的输入明确标为反例；习题给出提示及预期，留白不影响主工具。依赖版本和最小运行命令放 README，阶段文档保留逐步说明。

## 5. test 与 examples

本项目不另建 `examples/`。同一个 `.mlir` 既是阅读示例，也是工具的测试输入，统一放在 `test/E2E/mlir/stageXX/`。

```text
test/E2E/mlir/stage01/02-cse.mlir          输入
test/E2E/mlir/stage01/02-cse.expected.mlir 需要时才增加的期望 IR
test/E2E/mlir/stage07/add.json            需要时才增加的输入/期望运行值
test/E2E/resnet50/resnet50.onnx           用户模型
test/E2E/resnet50/resnet50_input.h        用户提供的模型输入
test/E2E/resnet50/resnet50_output.h       用户提供的期望输出
```

工具生成的 IR 写到用户指定路径，不覆盖输入和期望结果。小测试可把预期写在输入注释/阶段文档中；只有比较复杂或需要自动化时才拆 expected 文件或写 pytest。

`test/E2E/cpp/` 中有 C++ 文件不代表已经实现 C++ 前端；这是后续前端的输入存放处，也可容纳普通 C++ 构建练习。

## 6. pyproject.toml 是什么

它是 Python 项目的标准配置文件，常用于：

- 项目名、版本和依赖；
- 指定打包/构建工具；
- 配置 `pip install -e .` 可编辑安装；
- 安装 `my-opt` 一类命令入口；
- 保存 pytest 等工具的配置。

它**不是执行 Python 脚本的必要条件**。当前先用 `python tools/my_opt.py ...` 和现有环境，因此不创建它。将来需要稳定导入 `xdsl_mycompiler/` 或安装命令入口时，再讲解并引入最小配置。

Python 打包构建也不等价于 C++ 的编译链接；两条流程在涉及的阶段文件中分别讲。
